# 07 · 测试与验证方案

## 1. 测试分层

```
┌────────────────────────────────────────────┐
│ E2E：scripts/verify.sh（进程级黑盒验证）      │
├────────────────────────────────────────────┤
│ API 测试：internal/api（httptest + 临时DB）  │
├────────────────────────────────────────────┤
│ 服务层测试：internal/service（内存DB）       │
├────────────────────────────────────────────┤
│ 仓储/迁移测试：internal/store（内存DB）      │
├────────────────────────────────────────────┤
│ 纯函数测试：model / tlsutil / scheduler     │
└────────────────────────────────────────────┘
```

原则：
- 测试代码**不计入** 2000–2200 行约束（约束仅统计非 `_test.go` 的 `.go` 文件）；
- 所有测试不依赖外部网络/SMTP（webhook 用本地 `httptest.Server`，SMTP 用接口 mock）；
- DB 一律使用 `:memory:` SQLite，每个测试独立迁移。

## 2. 单元测试

### 2.1 internal/model（model_test.go，约 120 行）

### 2.2 internal/tlsutil（check_test.go，约 90 行）

- `VerifyTLS`：用 `httptest.NewTLSServer` + 自签证书验证"握手成功、序列号匹配、SAN 覆盖、过期拒绝"四条路径。

### 2.3 internal/task（scheduler_test.go，约 100 行）

- 注册重复任务报错；
- `TriggerNow` 同步执行并返回结果；
- 防重入：任务内阻塞时再次触发返回 `ErrTaskRunning`；
- `Stop` 优雅退出（任务完成计数正确）；
- 用短 Interval（10ms）验证 ticker 驱动。

## 3. 集成测试

### 3.1 internal/store（store_test.go，约 180 行）

- 迁移：`Migrate` 幂等（二次执行不报错）；`schema_migrations` 版本正确；
- CertStore：CRUD、软删除（Get 返回空、List 过滤）、状态过滤、分页、`ListDueForRenewal`、`ListExpiringWithin`；
- RenewalStore：`ListActiveForCert`（进行中判断）、状态更新；
- DeploymentStore / NotificationStore：基础 CRUD + 去重唯一索引（`INSERT OR IGNORE` 生效）；
- 审计写入与按资源过滤。

### 3.2 internal/service（certservice_test.go / renewalservice_test.go / notifyservice_test.go 等，约 380 行）

- certservice：登记初始状态正确；`RefreshStatus` 幂等（重复执行无二次审计）；状态变化触发 Dispatch（用记录型 mock 通知）；
- renewalservice：`Trigger` 成功创建 pending；重复触发 409；`force` 忽略阈值；流水线 issuing→issued→deploying→verifying→completed 全链路（mock Issuer + mock Deploy）；失败路径 → failed + 通知；
- deployservice：验证成功/失败/回滚（`rollback_on_fail`）；
- notifyservice：规则匹配（不匹配静默）、去重（24h 内第二条被忽略）、重试计数、Webhook 签名头存在。

## 4. API 测试（internal/api/api_test.go，约 200 行）

用 `httptest.NewServer(router)` 全量走 HTTP：

- 401：无/错 API Key；
- 证书：POST（201/400）、GET 列表（过滤+分页 total）、PUT、DELETE（204 且 GET 消失）、GET 详情 404；
- 续期：POST renew（202）、重复 409、retry 409（非 failed）；
- 任务：POST tasks/run（ok/404/409 running）；GET tasks 结构；
- 通知规则 CRUD 校验（webhook 缺 URL → 400）；
- 静态资源：GET /web/ 200（含 HTML）。

## 5. 端到端验证（scripts/verify.sh）

进程级黑盒验证，实现"完整验证"要求。流程：

```bash
#!/usr/bin/env bash
set -euo pipefail
# 0. 构建并启动服务（临时 DB）
go build -o /tmp/certlife-verify ./cmd/certlife
/tmp/certlife-verify -db /tmp/certlife-verify.db -addr 127.0.0.1:18080 &
PID=$!; trap 'kill $PID' EXIT
wait_health() { for i in $(seq 1 30); do curl -sf localhost:18080/api/v1/health && return; sleep 0.5; done; return 1; }
wait_health

# 1. 登记 3 张测试证书（近期到期 / 已过期 / 正常）
# 2. 手动触发 expiry_checker → 断言：近期到期→expiring_soon、已过期→expired、产生通知记录
# 3. 手动触发 renewal_runner（mock 签发）→ 断言 renewals 出现 issued→deploying 推进
# 4. 手动触发 deploy_verifier（target 为本地 tls 服务）→ 断言 deployments verification 通过、续期 completed
# 5. 手动触发 notify_dispatcher → 断言 renewal_succeeded 通知 sent
# 6. 断言审计日志包含 cert.create / cert.status_changed / renew.trigger / renew.result
# 7. 校验行数与文件数约束（调用 count_lines.sh）
echo "✅ 端到端验证通过"
```

配套：`scripts/verify.sh` 内嵌一个极简自签 TLS 测试服务（`scripts/fake_target/main.go`，约 40 行，供部署验证真实握手）。

## 6. 约束校验脚本（scripts/count_lines.sh）

```bash
#!/usr/bin/env bash
# 统计不含测试的 Go 代码行数与文件数，并断言约束
set -euo pipefail
FILES=$(find . -name '*.go' -not -name '*_test.go' -not -path './vendor/*' | sort)
LINES=$(cat $FILES | wc -l | tr -d ' ')
COUNT=$(echo "$FILES" | grep -c .)
echo "Go 文件数（不含测试）: $COUNT"
echo "Go 代码行数（不含测试）: $LINES"
[ "$COUNT" -gt 20 ] && [ "$COUNT" -lt 25 ] || { echo "❌ 文件数超出 (20,25)"; exit 1; }
[ "$LINES" -gt 2000 ] && [ "$LINES" -lt 2200 ] || { echo "❌ 行数超出 (2000,2200)"; exit 1; }
echo "✅ 约束满足：20 < 文件数 < 25，2000 < 行数 < 2200"
```

> 说明：行数以 `wc -l` 实际统计为准；若实现后偏离预算，通过增删注释与工具函数微调至区间内（预算见 08）。

## 7. 覆盖与验收清单

### 覆盖率目标（`go test -cover`）

- model ≥ 90%；tlsutil ≥ 85%；store ≥ 80%；service ≥ 75%；api ≥ 70%；task ≥ 70%；整体 ≥ 75%。

### 验收清单（对应业务规则）

- [ ] 登记校验：`valid_from < valid_until` 强制；
- [ ] 到期检查幂等：二次执行无重复状态变更/通知；
- [ ] 自动续期仅处理符合策略的证书；
- [ ] 并发续期保护返回 409；
- [ ] 续期失败自动重试 ≤ 2 次后通知；
- [ ] 部署验证四项（握手/序列号/SAN/有效期）全过才 completed；
- [ ] 通知去重与重试（≤3 次）；
- [ ] 所有写操作产生审计日志；
- [ ] 软删除后列表不可见；
- [ ] 行数 ∈ (2000, 2200)、文件数 ∈ (20, 25)；
- [ ] `go vet ./...`、`gofmt -l .` 无输出；
- [ ] `scripts/verify.sh` 全绿。

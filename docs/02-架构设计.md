# 02 · 架构设计

## 1. 分层架构

严格单向依赖，上层依赖下层，下层不反向依赖：

```
┌─────────────────────────────────────────────────────────────────────┐
│                             web/ (前端)                              │
│              index.html · app.js · style.css（embed 提供）            │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ HTTP (fetch /api/v1/*)
┌───────────────────────────────▼─────────────────────────────────────┐
│                          internal/api                                │
│              router.go · handlers.go · handler_*.go                  │
│          职责：路由、鉴权/日志/恢复中间件、参数解析、响应封装           │
└───────┬───────────────────────────────┬─────────────────────────────┘
        │ 调用                          │ 调用
┌───────▼──────────────────────┐ ┌──────▼──────────────────────────────┐
│     internal/service         │ │        internal/task                │
│   certservice / renewalsvc   │ │   scheduler.go · jobs.go            │
│   deployservice / notifysvc  │ │  职责：5 个定时任务、手动触发、调度   │
│   stats                      │ │                                     │
│  职责：业务规则、状态机、编排  │ │                                     │
└───────┬──────────────────────┘ └───────┬─────────────────────────────┘
        │ 调用                          │ 调用
┌───────▼────────────────────────────────▼────────────────────────────┐
│                        internal/store                                │
│   db.go(迁移) · certstore · renewalstore · deploymentstore ·         │
│   notificationstore                                                  │
│  职责：SQLite 持久化、仓储接口实现、迁移执行、事务                      │
└───────┬──────────────────────────────────────────────────────────────┘
        │ 依赖
┌───────▼──────────────────────┐ ┌────────────────────────────────────┐
│      internal/model          │ │       internal/tlsutil             │
│   Certificate/Renewal/       │ │   PEM 解析、TLS 握手校验、           │
│   Deployment/Notification/   │ │   指纹/SAN 校验（纯函数，无 IO）      │
│   AuditLog + 状态枚举         │ │                                     │
└──────────────────────────────┘ └────────────────────────────────────┘
        ▲
        │ 读取
┌───────┴──────────────────────┐
│      internal/config         │
│   Config 结构 + 默认值 + 解析 │
└──────────────────────────────┘
        ▲
┌───────┴──────────────────────┐
│      cmd/certlife/main.go    │  入口：装配依赖、启动 HTTP 与调度器
└──────────────────────────────┘
```

依赖方向（不允许反向）：

```
main → config, store, service, task, api, model
api  → service, model
task → service, model, store
service → store, model, tlsutil
store → model
```

## 2. 各层职责与关键接口

### 2.1 cmd/certlife/main.go（入口，约 70 行）

1. 解析 `-config` flag 与 `-addr`、`-api-key`、`-db` 覆盖；
2. `config.Load()` 得到 Config；
3. `store.Open(cfg)` → 执行迁移 → 得到 `*sql.DB`；
4. 构建各 `store` 与 `service`；
5. 构建 `task.Scheduler` 并注册 5 个任务，`Start()`；
6. 构建 `api.NewRouter(deps)`，`http.Server` 启动；
7. 监听 SIGINT/SIGTERM，优雅关闭（HTTP 停机 + 调度器 Stop + DB Close）。

### 2.2 internal/config（约 90 行）

```go
type Config struct {
    Addr       string        // HTTP 监听地址，默认 127.0.0.1:8080
    DBPath     string        // SQLite 路径，默认 ./certlife.db
    APIKey     string        // X-API-Key，默认 dev-key
    WebDir     string        // 前端目录，默认内嵌 embed
    SMTP       SMTPConfig    // Host/Port/User/Pass/From/UseTLS
    Webhook    WebhookConfig // 默认签名密钥
    Scheduler  SchedulerConfig // 各任务间隔（Go duration 字符串）
}
func Load(path string) (Config, error)   // 读取 YAML + 环境变量覆盖 + 默认值
```

环境变量覆盖：`CERTLIFE_ADDR`、`CERTLIFE_DB`、`CERTLIFE_API_KEY`、`CERTLIFE_SMTP_*`。

### 2.3 internal/model（约 290 行，5 个文件）

纯数据结构 + 枚举 + 校验函数，**不依赖任何其他包**（除标准库）：

- `Certificate`：`ID, Name, Domain, SANs, Issuer, SerialNumber, Algorithm, KeyBits, ValidFrom, ValidUntil, Owner, Environment, Tags, Contacts, NotifyThresholdDays, RenewThresholdDays, AutoRenew, DeployTargetIDs, Status, DaysToExpire, LastCheckedAt, CreatedAt, UpdatedAt, DeletedAt`
- `CertificateStatus`：`StatusValid / StatusExpiringSoon / StatusExpired`
- `Renewal` + `RenewalStatus`（7 态）
- `DeploymentTarget` / `Deployment` / `VerificationResult`
- `Notification` / `NotificationRule` / `NotificationStatus` / `EventType`
- `AuditLog` / `Action`
- 校验：`Certificate.Validate()`（valid_from < valid_until、域名非空、阈值 ≥ 0）、`Renewal.Transitions` 合法性等。

### 2.4 internal/store（约 465 行，5 个文件）

- `db.go`：`Open(path)`、`Migrate(db)`（内嵌迁移 SQL 列表 + `schema_migrations` 版本表 + 事务执行 + `user_version`）、`Ping`；
- 各 store 为**具体类型**（MVP 不做接口抽象，避免样板代码膨胀）：
  - `CertStore`：`Create/Get/Update/Delete(软删)/List(filter, page, size)/CountByStatus/ListExpiringWithin(days)/ListDueForRenewal(threshold)`
  - `RenewalStore`：`Create/Get/ListByCert/ListActiveForCert/UpdateStatus/ListRetryable`
  - `DeploymentStore`：`CreateTarget/ListTargets/GetTarget/CreateDeployment/UpdateDeployment/ListByRenewal/ListByCert`
  - `NotificationStore`：`Create/List/UpdateStatus/CountToday/ListPending/DedupExists`、`RuleCreate/List/Update/Delete`、审计 `AuditAdd/ListAudits`
- 所有写方法在单事务内完成（`db.BeginTx`），便于后续扩展多表一致性。

### 2.5 internal/service（约 460 行，5 个文件）

业务规则全部收敛在 service 层：

- `certservice`：`Register`（校验 + 初始状态 + 审计）、`Update`、`Delete`（软删）、`List/Get`、`RefreshStatus`（到期状态推进，幂等，供任务调用）、`GetStats` 数据准备；
- `renewalservice`：`Trigger`（自动/手动、409 保护、审计）、`RunPipeline`（状态机推进）、`RetryFailed`、`CompleteOrFail`；
- `deployservice`：`Deploy`（按目标方法下发）、`Verify`（调 tlsutil + 写部署记录 + 回滚）、`ListByCert`；
- `notifyservice`：`Dispatch(event, cert)`（规则匹配 → 去重 → 建记录）、`SendPending`（SMTP/Webhook 发送 + 状态回写 + 重试）、`SendDailySummary`、`Render`（模板拼接标题/正文）；
- `stats`：`DashboardStats`（一次查询聚合）。

### 2.6 internal/task（约 265 行，2 个文件）

- `scheduler.go`：任务注册表 `map[string]*Job{Name, Interval, Run func(ctx) Result}`；主循环用 `time.Ticker` 按各自间隔触发；支持 `TriggerNow(name)`（手动，API 调用）；记录每次执行开始/结束/错误；`Start/Stop` 优雅退出（`context.WithCancel` + `WaitGroup`）；
- `jobs.go`：5 个任务实现：
  1. `expiry_checker`（每 6h）：`certservice.RefreshAllStatus` + 生成到期告警 + 统计；
  2. `renewal_runner`（每 1h）：查 `ListDueForRenewal` → `renewalservice.Trigger(auto)` → 处理 `failed` 重试（≤2 次）；
  3. `deploy_verifier`（每 30m）：处理 `issued/deploying` 中未完成的续期 → 部署 → 验证；
  4. `notify_dispatcher`（每 5m）：`notifyservice.SendPending`；
  5. `daily_summary`（每天 09:00）：生成并发送 `daily_summary` 通知。

### 2.7 internal/api（约 460 行，5 个文件）

- `router.go`：`http.ServeMux` 注册；中间件链：`recover → accessLog → auth(APIKey)`；`/web/*` 静态资源（embed）；CORS 允许同源；
- handlers：见 [docs/04-API设计.md](docs/04-API设计.md)；统一响应结构 `{code, message, data}`；错误码 400/401/404/409/500。

### 2.8 internal/tlsutil（约 75 行）

纯函数，可单测：
- `ParsePEM(data []byte) (*x509.Certificate, error)`；
- `VerifyTLS(host string, port int, wantSerial string, wantSANs []string) (VerificationResult, error)`：`tls.Dial` + 校验链 + 序列号 + SAN 覆盖 + 有效期；
- `FingerprintSHA256(cert *x509.Certificate) string`。

## 3. 关键流程时序

### 3.1 登记证书（同步）

```
前端/curl → api.PostCertificate → certservice.Register
  ├─ model.Certificate.Validate()
  ├─ 计算 DaysToExpire 与初始 Status
  ├─ certStore.Create(tx)
  └─ auditStore.Add("cert.create") → 201 {certificate}
```

### 3.2 手动续期（同步触发 + 异步流水线）

```
前端 → api.PostRenew → renewalservice.Trigger(certID, force)
  ├─ 校验存在、无进行中续期（有则 409）
  ├─ renewalStore.Create(pending) + audit("renew.trigger")
  └─ 返回 202 {renewal}
后台 deploy_verifier / renewal_runner 轮询：
  renewalservice.RunPipeline(renewal)
    issuing → issuer.Issue(cert) → 得 new_serial → issued
    deploying → deployservice.Deploy 到每个 target → deploying
    verifying → deployservice.Verify（tlsutil）→ completed / failed
  完成/失败 → 审计 + notifyservice.Dispatch(renewal_succeeded | renewal_failed)
```

### 3.3 到期检查（异步，幂等）

```
ticker → expiry_checker → certservice.RefreshAllStatus
  ├─ 逐证书计算新状态；仅当状态变化才 Update + audit("cert.status_changed")
  └─ 变化且进入 expiring_soon/expired → notifyservice.Dispatch
```

### 3.4 通知发送

```
notify_dispatcher → notifyservice.SendPending
  ├─ 取 pending 记录（含 failed 重试）
  ├─ 通道发送（SMTP/Webhook），带 HMAC 签名头
  └─ 成功 → sent；失败 → failed + retry_count，达到 3 次不再重试
```

## 4. 错误处理与日志

- service 层返回领域错误（`ErrNotFound / ErrConflict / ErrValidation`），api 层映射为 HTTP 状态码；
- 后台任务错误不回滚业务数据（任务幂等），仅记录 `task_last_error` 并可通过 `GET /api/v1/tasks` 查询；
- 日志用标准库 `log/slog`，级别 info/warn/error；不记录私钥、密码、API Key 明文。

## 5. 并发与一致性

| 关注点 | 方案 |
|--------|------|
| 单证书并发续期 | 触发时 `SELECT ... WHERE cert_id=? AND status IN (active)` 冲突则 409；SQLite 写锁兜底 |
| 到期状态唯一写路径 | 仅 `RefreshStatus` 修改状态，任务与 API 都走它 |
| 通知去重 | `notifications` 上 `(certificate_id, event_type, date)` 唯一索引 + `INSERT OR IGNORE` |
| 任务并发 | 每个任务同一时刻只跑一轮（`sync.Mutex` 防重入），调度器单协程驱动 |

## 6. 可扩展点

- `Issuer` 接口：`Issue(ctx, cert) (*IssuedCert, error)`，MVP 提供 `mockIssuer`，后续接 ACME；
- `Notifier` 接口：`Send(ctx, msg) error`，MVP 提供 `smtpNotifier` 与 `webhookNotifier`；
- `store` 各仓储方法签名按表操作划分，换 PostgreSQL 只需重写实现；
- 调度器间隔全部走配置，支持在 `config.yaml` 调频。
